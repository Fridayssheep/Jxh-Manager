# 移除旧 QQ 内置管理命令设计

## 背景

Bot 当前同时存在两套命令机制：

- `GroupCommandRouter` 直接识别并执行 `/test`、`/reload`、`/q`、`/ai` 和 `/admin`；
- 管理面板维护数据库驱动的受控自定义命令。

其中知识库重载已经由管理面板完整承接。前端知识库页面通过 `POST /api/admin/v1/knowledge/reload` 启动重载，后端执行权限、CSRF、幂等、防并发、超时、状态持久化和失败保留旧索引。因此 QQ `/reload` 不再承担不可替代的能力。`/admin` 下的运维与运营入口也不再作为 QQ 命令维护，`/test` 则没有继续保留的必要。

## 目标

1. 完全移除 `/test`、`/reload` 和 `/admin` 的 QQ 内置命令实现。
2. 保留 `/ai` 和 `/q` 两个内置业务命令及其现有功能开关。
3. Bot 被单独 `@` 时，只展示 `/ai` 和 `/q` 的简化帮助菜单。
4. 从自定义命令保留名中释放 `/test`、`/reload` 和 `/admin`。
5. 删除仅为旧 QQ 管理命令服务的装配依赖和无引用代码。

## 非目标

- 不删除管理面板中的知识库重载、NapCat 重启、定时任务、入群审批、统计或导出能力。
- 不修改 `/ai`、`/q` 的参数、权限或执行逻辑。
- 不提供旧命令的弃用回复或跳转提示；旧命令未被注册为自定义命令时按普通未命中消息处理。
- 不为释放后的 `/admin` 名称赋予任何特殊权限。若管理员将其创建为自定义命令，它只具备自定义命令引擎允许的受控动作和配置权限。

## 后端改动

### 命令路由

`GroupCommandRouter` 只处理 `/ai` 和 `/q`。删除：

- `/test`、`/reload`、`/admin` 的路由分支；
- 重载、原生管理员授权、禁言、NapCat 重启、旧定时任务管理、群申请导出和词条统计相关处理函数；
- 仅被这些分支使用的字段、接口、导入、常量和帮助文本。

内置路由仍先于自定义命令执行。由于三个旧名称不再被内置路由消费，它们可以继续进入自定义命令匹配阶段。

### 装配与旧包

从 `bot.Options` 和 `cmd/bot` 组合根中移除只服务于旧 QQ 命令的 `Reloader` 与 `AdminHandler` 装配。知识库运行时、管理 API、调度执行器、入群申请采集和统计服务继续保留。

若 `internal/bot/commands` 在移除装配后没有其他调用方，则删除该包；不保留不可达的兼容实现。

### 自定义命令注册表

默认保留名从五个缩减为：

```text
/ai
/q
```

`/test`、`/reload`、`/admin` 随即可以作为普通自定义命令名称创建，但仍受作用群、触发权限、动作白名单和审计规则约束。

## 前端与 API

本次不新增或修改管理 API。知识库重载继续使用现有接口和知识库页面；其他管理功能继续使用现有面板入口。

## 测试

1. 路由测试确认 `/test`、`/reload`、`/admin` 不再被内置命令处理。
2. 管线测试确认这些名称能够下沉到自定义命令执行器。
3. 注册表测试确认三个名称可以注册，而 `/ai`、`/q` 仍然冲突。
4. 帮助菜单测试确认只包含 `/ai` 和 `/q`。
5. 全量运行 Go 测试、构建、`go vet` 和 `go mod tidy -diff`。

## 验收标准

- 仓库中不存在旧 QQ 命令的路由、帮助说明和专用处理代码。
- `internal/bot/commands` 不再存在或仍存在明确的非旧命令调用方。
- 管理面板知识库重载相关前后端测试继续通过。
- `/ai`、`/q` 行为保持不变。
- `/test`、`/reload`、`/admin` 可以由受控自定义命令使用。
