# 群列表自动入群审核控制设计

- 日期：2026-07-31
- 状态：已确认，待实施
- 范围：管理端群目录、群资源接口与群级入群策略摘要

## 1. 目标

管理员应当能在“群与设置”的群目录中直接查看并修改每个群的自动入群处理策略，无需等待该群出现入群申请，也无需进入申请详情。

群列表同时展示两个相互独立的群级开关：

- 自动批准：AI 字段完整且格式有效时自动批准。
- 自动拒绝：AI 字段无效时使用全局拒绝消息自动拒绝。

入群审批详情中的现有策略入口继续保留。两个入口读写同一个 `group_join_policies` 资源。

## 2. 数据契约

`Group` 资源增加必填的 `join_request_policy` 摘要：

```json
{
  "enabled": false,
  "auto_reject": false,
  "version": 1
}
```

摘要随 `GET /api/admin/v1/groups` 和 `GET /api/admin/v1/groups/{group_id}` 返回。群列表不得为每一行额外请求策略接口。

摘要字段语义：

- `enabled` 对应自动批准开关。
- `auto_reject` 对应自动拒绝开关。
- `version` 是策略资源版本，而不是群快照版本。

写入继续使用现有端点：

```http
PATCH /api/admin/v1/groups/{group_id}/join-request-policy
If-Match: "<policy-version>"
```

请求只提交被切换的字段。成功响应仍为完整 `JoinRequestPolicy`，前端将其中三个摘要字段回写到对应群行。

## 3. 后端实现边界

群目录存储查询在读取 `managed_groups` 时关联 `group_join_policies`，一次得到策略摘要，避免前端 N+1 请求。

群同步已经为每个受管群创建默认策略，因此 `join_request_policy` 对正常群资源为必填值。默认状态保持：

- `enabled: false`
- `auto_reject: false`
- `version: 1`

如果持久化数据违反该不变量，接口返回现有内部数据错误，不伪造可修改的临时版本。

OpenAPI 3.1 增加 `JoinRequestPolicySummary`，并将其作为 `Group.join_request_policy` 的必填属性。生成的 TypeScript 类型随契约更新。

## 4. 前端交互

群目录新增“自动审核”列。每行包含两个紧凑开关，分别标为“批准”和“拒绝”。开关使用现有品牌色、焦点样式和二元控件语义，不使用下拉菜单或文字按钮替代。

权限行为：

- 拥有 `join_policies:write` 的超级管理员可以切换。
- 其他角色可以查看状态，但开关保持禁用。
- 权限判断沿用现有认证上下文，不在前端推断角色名称。

保存行为：

1. 用户切换某一字段。
2. 仅该行进入忙碌状态，该行两个开关同时禁用，其他群仍可操作。
3. 前端使用该行策略 `version` 发起 PATCH，只提交被修改字段。
4. 成功后以响应中的 `enabled`、`auto_reject`、`version` 替换该行摘要。
5. 页面通过 `OperationNotice` 显示带群名和策略名称的成功提示，并使用既有上浮动画。

前端不提前改写开关状态，以服务端响应作为最终状态，避免请求失败时出现错误的短暂状态。

## 5. 错误与并发

- `409 resource_version_conflict`：重新查询群列表以取得最新策略版本，保留当前筛选条件，并提示策略已被其他管理员修改。
- 其他 API 错误：保持原策略状态，显示服务端错误消息。
- 网络错误：保持原策略状态，显示统一连接失败消息。
- 单行忙碌期间重复点击不再发起请求。

冲突刷新不清除已加载群列表的筛选条件，不跳转页面，也不影响其他行的交互状态。

## 6. 响应式布局

- 桌面：保留现有群信息、功能摘要和操作列，新增独立“自动审核”列。
- 平板：继续隐藏现有功能摘要列，保留自动审核列和详情入口。
- 移动端：群目录保持卡片布局；自动审核占满独立一行，两个开关并排显示，不挤压群名、人数和详情入口。

所有开关和标签必须在 `1440x1024`、`1024x768`、`390x844` 三种验收视口内无横向溢出、文字截断或控件重叠。

## 7. 测试与验收

后端测试覆盖：

- 群列表和详情响应包含策略摘要。
- 策略摘要来自同群 `group_id`，两个群的状态不会串行。
- 新同步群的两个开关默认关闭且版本为 1。
- OpenAPI 要求 `Group.join_request_policy` 和三个摘要字段。

前端单元测试覆盖：

- 两个开关显示独立状态。
- 超级管理员可操作，其他角色只读。
- 自动批准和自动拒绝分别提交最小 PATCH 与正确版本。
- 保存期间只禁用当前行。
- 成功响应更新行状态和版本。
- 409 重新加载并显示冲突提示，其他错误保持原状态。

E2E 覆盖：

- 群列表修改两个策略时发送正确的 `If-Match` 和 CSRF 请求。
- 三种视口内自动审核列或卡片行可见且无横向溢出。
- 入群审批详情中的原策略入口仍可使用。

最终执行后端相关测试、前端全量单测、完整 E2E、生产构建、ESLint、Oxlint 和差异检查。

## 8. 非目标

- 不新增全局自动批准或自动拒绝开关。
- 不改变 AI 字段判定规则、全局拒绝消息或自动处理 worker 的决策语义。
- 不新增批量修改多个群策略的能力。
- 不移除入群审批详情中的现有策略入口。
