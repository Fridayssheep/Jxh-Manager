# Jxh Manager 管理面板总体设计

- 日期：2026-07-27
- 状态：已确认
- 适用仓库：`Jxh-Manager`
- 后端参考：`Resource/Jxh-Go`

## 1. 背景与结论

Jxh-Go 已经具备关键词回复、AI 知识问答、引用图、链接净化、入群申请采集、定时任务和词条统计等能力，但管理入口主要是 QQ 群命令和本地导出文件。当前 HTTP 服务只有 `/healthz`，没有管理 API、Web 登录、角色权限或审计机制。

管理面板不能只新增一个前端。首版采用“同进程模块化管理端”：在现有 Go bot 进程中新增管理 HTTP API、鉴权、应用服务和数据持久化，直接复用唯一的 NapCat 连接、知识索引、调度器和存储层；前端作为独立 SPA 构建并部署。

这一选择避免出现两套 NapCat 连接、两套运行时配置或 Web 与 QQ 命令行为不一致。模块边界仍需保持清晰，使未来拆分独立 Manager 服务时不必重写业务规则。

## 2. 产品目标

管理面板面向 bot 内部维护团队，不面向各 QQ 群群主或群管理员开放登录。

首版目标：

1. 使用本地独立账号完成安全登录，并提供超级管理员、维护员、观察员三档角色。
2. 集中查看 bot、NapCat、MySQL、WPS、AI 和引用图服务的运行状态。
3. 使用全局默认值和群级覆盖控制现有功能及文案。
4. 查看、人工处理并按群启用自动处理入群申请。
5. 通过受控动作模板创建自定义命令，包括回复文本、@成员、禁言和向允许的群发送消息。
6. 完整管理每天与单次定时任务，并查看执行结果。
7. 保持 WPS 为知识库唯一数据源，在面板中提供只读预览、同步状态和手动重载。
8. 展示现有业务统计和新增运营统计，同时避免长期存储完整群消息正文。
9. 对配置修改、审批和高风险操作建立可追踪的审计记录。

## 3. 非目标

首版不包含：

- 面向 QQ 群管理员的多租户登录和按群数据隔离。
- 在面板内编辑知识词条或把修改写回 WPS。
- 任意脚本、Shell、SQL 或用户提供的代码执行。
- 自定义命令调用任意外部 HTTP 地址。
- 仅依靠 AI 结果自动拒绝入群申请。
- 在管理面板中编辑或返回 OneBot Token、WPS SID、AI Key、数据库密码等密钥。
- 本文不内嵌最终视觉风格、色彩令牌和详细响应式布局；这些由 `2026-07-28-jxh-manager-ui-design.md` 定义。

## 4. 现有能力与管理端配合方式

| 现有能力 | 当前实现 | 管理面板职责 | 必要后端补充 |
| --- | --- | --- | --- |
| 关键词回复 | WPS 导入后内存精确匹配 | 开关、只读预览、触发统计 | 运行时设置查询与更新 |
| `/ai` | Eino Agent 检索内存知识库，最多并发 2 个请求 | 全局/按群开关、使用量、成功率、耗时 | 功能设置与运营事件 |
| `/q` 引用图 | 调用 quote 服务，GIF 失败回退 PNG | 开关、成功/回退/失败统计、服务状态 | 运行时设置与事件记录 |
| 链接净化 | 自动处理 Bilibili/小红书链接 | 开关、净化次数与失败统计 | 运行时设置与事件记录 |
| 欢迎消息 | 新成员入群后发送硬编码消息 | 开关、全局文案、群级文案覆盖 | 可验证的消息模板设置 |
| 入群申请 | 实时和轮询采集、AI 提取字段、本地 XLSX 导出 | 待办队列、详情、批准/拒绝、批量处理、自动批准 | NapCat 审批调用、决策状态、并发控制、审计 |
| 定时任务 | 每天/单次任务，可添加、查看、软删除 | 创建、编辑、暂停、恢复、测试发送、执行历史 | 更新接口与执行记录 |
| 词条统计 | 记录关键词回复和 AI 检索，导出 XLSX | 图表、排行、筛选、下载 | 管理 API 和可下载导出 |
| 群管理命令 | 实时查询群角色，支持禁言和 NapCat 重启 | 受控操作、确认、审计 | Web RBAC 和高风险操作服务 |
| 健康检查 | `/healthz` 固定返回 `ok` | 依赖健康、最近成功时间和故障提示 | 存活与就绪状态分离 |

## 5. 总体架构

```text
Admin SPA
   |
   | HTTPS + JSON API + Secure Session Cookie
   v
Admin HTTP API
   |
   +-- Auth / RBAC / CSRF
   +-- Settings application service
   +-- Command application service
   +-- Join-request application service
   +-- Scheduler application service
   +-- Analytics / Audit application service
   |
   v
Existing runtime services in the same jxh-go process
   +-- Pipeline and command router
   +-- NapCat sender and OneBot WebSocket
   +-- Knowledge index and WPS syncer
   +-- Scheduler runtime
   +-- Storage and trigger statistics
   |
   +-- MySQL
   +-- WPS knowledge sheet (read-only source)
   +-- NapCat / Quote / AI providers
```

### 5.1 模块边界

- HTTP handler 只负责鉴权、权限检查、输入解码、输出编码和错误映射，不直接调用 GORM 或拼装 OneBot 请求。
- 应用服务承载完整业务规则，并同时供管理 API 与已有 QQ 管理命令复用。
- NapCat、WPS、AI、quote 和数据库通过现有适配层或扩展后的适配层访问。
- 配置、命令和健康状态形成只读运行时快照；消息管线读取快照，不在每条消息上访问数据库。
- 管理 HTTP 服务必须有独立的 panic 恢复、超时和并发限制，不能阻塞 NapCat 事件处理。

### 5.2 前端交付形态

前端作为独立 SPA 工程构建。生产环境可以由 Go 服务托管静态产物，也可以由同一部署中的反向代理提供；无论采用哪种方式，浏览器只访问管理 API，不直接连接 MySQL、NapCat 或其他内部服务。

需要实时更新的待审批数量、服务状态和操作结果使用 SSE。普通读取和写入继续使用 REST，首版不引入双向 WebSocket 管理协议。

## 6. 登录、会话与权限

### 6.1 本地账号

- 不允许自助注册，也不提供默认账号或默认密码。
- 首个超级管理员通过一次性 CLI 引导创建；后续账号由超级管理员在面板中创建、停用或重置密码。
- 密码使用 Argon2id 加随机盐保存，并在记录中保存参数版本以便未来升级。
- 登录失败采用账号与来源地址双维度速率限制，但返回统一错误，避免枚举账号。

### 6.2 会话

- 使用服务端会话和随机高强度令牌；浏览器只保存 `HttpOnly`、`Secure`、`SameSite=Strict` Cookie。
- 所有状态修改请求要求 CSRF Token，并验证 `Origin`。
- 登录后轮换会话令牌；退出、停用账号和密码重置会撤销该用户现有会话。
- 会话采用有限空闲时长和绝对有效期，超级管理员可以查看并撤销会话。
- 生产部署必须通过 HTTPS；反向代理信任范围显式配置，不能无条件相信转发头。

### 6.3 角色矩阵

| 能力 | 超级管理员 | 维护员 | 观察员 |
| --- | --- | --- | --- |
| 查看总览、群、知识库和统计 | 是 | 是 | 是 |
| 查看申请详情和验证信息 | 是 | 是 | 否 |
| 批准/拒绝申请 | 是 | 是 | 否 |
| 修改功能设置、命令和定时任务 | 是 | 是 | 否 |
| 手动重载 WPS 知识库 | 是 | 是 | 否 |
| 查看审计日志 | 是 | 是 | 是，隐藏敏感详情 |
| 管理账号和会话 | 是 | 否 | 否 |
| 修改自动批准开关、跨群发送策略 | 是 | 否 | 否 |
| 请求重启 NapCat | 是 | 否 | 否 |

权限必须在后端执行。前端隐藏按钮只是交互优化，不构成授权机制。

## 7. 信息架构与页面范围

### 7.1 总览

- 展示待处理申请、今日自动批准、命令调用、活跃群、启用任务和依赖健康等关键指标。
- 展示最近 7 天、30 天或自定义范围的趋势。
- 使用“需要处理”区域聚合长时间未审批申请、失败任务、WPS 冲突和服务降级。
- 所有指标可跳转到带对应筛选条件的详细页面。

### 7.2 群管理

- 从 NapCat 获取 bot 所在群列表，显示群名、群号、成员数、bot 群角色、连接可用性和最近同步时间。
- NapCat 不可用时展示最后一次成功快照，并明确标记为陈旧数据。
- 群详情集中展示功能覆盖设置、欢迎文案、自动批准状态、定时任务和近期活动。
- 群级设置使用“继承/启用/停用”三态，不复制整份全局配置。

### 7.3 入群审批

- 默认进入待处理队列，支持按群、时间、AI 解析状态、处理来源和决策状态筛选。
- 详情展示申请人 QQ、验证消息、AI 提取字段、解析状态、原始申请时间和已有决策记录。
- 支持单条批准、拒绝和同群批量处理；批量操作先展示影响数量并二次确认。
- 列表和详情通过 SSE 接收入库、解析完成和决策变化，避免依赖高频轮询。
- 自动批准必须展示命中的确定性条件和执行结果，不以“AI 判断”作为模糊理由。

### 7.4 命令管理

- “内置能力”页面控制关键词回复、`/ai`、`/q`、链接净化和欢迎消息。
- `/test`、鉴权与权限检查不可关闭；`/reload` 和系统管理动作不作为普通群功能下放。
- “自定义命令”页面提供列表、创建/编辑表单、参数定义、动作编排、作用群、触发权限、启停和只读执行记录。
- 发布前提供纯解析和模板渲染测试；测试默认不产生禁言、跨群发送等外部副作用。

### 7.5 定时任务

- 支持每天和单次任务的创建、编辑、暂停、恢复和停用。
- 新增“测试发送”，它立即发送一次但不修改正式任务的 `last_run_at`。
- 展示最近执行时间、下次预计执行时间和执行历史。
- 单次任务成功后自动停用；发送失败时保留任务等待后续重试，延续现有语义。

### 7.6 知识库

- 展示 WPS 来源、sheet、最近同步结果、缓存更新时间、词条数量、冲突数量和错误摘要。
- 支持手动重载、按关键词/分类/状态搜索和只读预览词条。
- 不编辑词条，不返回 WPS SID，不改变 WPS 唯一真源地位。
- WPS 下载为空、解析失败或出现无有效词条时，不替换当前索引和有效缓存。

### 7.7 统计

- 业务统计：关键词回复、AI 检索、入群申请、人工/自动批准和定时任务。
- 运营统计：群消息量、命令调用、去重活跃用户、AI 成功率与耗时、链接净化、引用图成功/回退/失败。
- 支持按群、功能、结果和时间范围筛选，并提供 XLSX/CSV 下载。
- 总览只展示聚合信息，详细页负责排行、趋势和失败分布。

### 7.8 审计、账号与系统

- 审计日志按操作者、动作、目标、结果和时间筛选，详情展示变更前后值与错误代码。
- 账号页管理用户、角色、状态、密码重置和活动会话。
- 系统页展示各依赖的状态与最近成功时间，只显示密钥是否已配置，不显示密钥内容。
- NapCat 重启属于超级管理员高风险操作，需要再次确认，并记录请求和结果。

## 8. 功能设置模型

首版可配置功能键：

- `keyword_reply`
- `ai_qa`
- `quote`
- `link_cleaner`
- `welcome`
- `custom_commands`

每个功能具有全局设置。群级覆盖不存在时继承全局值；存在时可单独覆盖启停和该功能允许覆盖的配置字段。欢迎消息支持受控模板变量，例如新成员 QQ 或群名称；未知变量在保存时拒绝，而不是运行时原样泄漏。

设置写入流程：

1. 校验角色、字段和修订版本。
2. 在事务内写入设置和审计记录。
3. 构建新的不可变运行时快照。
4. 原子替换当前快照。

输入校验或快照构建失败时不提交修改。消息管线始终看到完整旧快照或完整新快照，不读取中间状态。

## 9. 自定义命令引擎

### 9.1 命令定义

- 命令名称使用完整 `/name` 形式，只允许安全字符并限制长度。
- 不允许与内置命令重名，也不使用宽泛前缀把 `/air` 识别成 `/ai`。
- 参数类型包括文本、整数、正时长、QQ 成员和固定选项；定义中明确参数顺序、是否必填和边界。
- 作用域支持全局或指定群。
- 触发权限支持所有成员、当前群 owner/admin、维护 QQ 白名单。

### 9.2 动作模板

首版动作白名单：

1. `reply_text`：向触发群回复模板文本。
2. `mention`：@触发者或成员参数指定的用户。
3. `mute_member`：按时长参数或固定时长禁言成员。
4. `send_group_text`：向命令定义中显式允许的群发送文本。

动作数量、模板长度、单次执行时间和发送目标数量都有硬限制。禁言和跨群发送命令不能配置为“所有成员可触发”。跨群目标必须在命令保存时固定选择，不能由普通文本参数提供任意群号。

维护员可以配置文本回复、@成员和当前群禁言动作。新增或修改 `send_group_text` 的跨群目标属于超级管理员权限；维护员只能查看此类命令或启停已经获批且目标未变化的定义。

动作按顺序执行，出现失败后停止后续动作。OneBot 外部副作用不能回滚，因此执行记录必须标明每一步结果，不能把部分成功报告成完全成功。

### 9.3 管线顺序

消息处理顺序保持可预测：

1. 内置命令完整匹配。
2. 自定义 `/命令` 完整匹配、参数解析和权限检查。
3. 链接净化。
4. 关键词精确回复。

保存命令时完成冲突检查，运行时不允许后发布的命令静默覆盖已有定义。

## 10. 入群申请与自动批准

### 10.1 唯一标识与状态

继续使用 NapCat `GroupNotify.seq` 对应的 `flag/request_id` 作为唯一业务标识，不新增平行身份字段，不截断、哈希或伪造该值。

管理端扩展可区分的业务状态：待处理、处理中、已批准、已拒绝、外部已处理和结果未知。“处理中”是短暂的并发占用状态，并由超时恢复任务处理进程异常留下的记录。系统轮询只能看到 `checked` 时，不得覆盖管理端已经确认的批准或拒绝结果。

### 10.2 人工决策流程

1. 读取当前记录及修订版本。
2. 校验记录仍为待处理，并校验操作者权限。
3. 在数据库事务中用条件更新把记录从“待处理”原子改为“处理中”，同时写入带幂等键的决策尝试；只有成功占用记录的请求可以继续。
4. 使用原始 `flag` 调用 NapCat `set_group_add_request`。
5. 调用明确成功后写入最终状态和决策结果；明确失败时按错误类型恢复待处理或保留失败记录，超时等不明确结果进入“结果未知”。
6. 发布 SSE 更新并刷新列表。

每个决策请求携带幂等键和记录修订版本。多人同时处理同一申请时，只有第一个合法决策进入 NapCat 调用，其余请求返回冲突并刷新最新状态。

### 10.3 自动批准规则

自动批准按群配置，默认关闭。仅处理 `sub_type=add` 且仍为待处理的申请，并同时满足：

- AI 解析状态为 `completed`。
- 学号、姓名、专业三个字段均非空。
- 学号、姓名、专业分别通过与现有解析边界一致的确定性格式校验。
- 该申请没有正在执行、失败待核验或结果未知的决策。

满足条件后系统可以自动批准，但不自动拒绝。自动决策记录规则版本、字段快照和明确原因。调用失败时记录尝试并保留人工处理能力；超时等结果不明确的情况先标记“结果未知”并重新同步 NapCat 状态，不盲目重复批准。

未来接入权威名单时，在自动批准服务中增加名单匹配条件，不改变审批页面和 NapCat 调用边界。

## 11. 统计与隐私

现有 `knowledge_trigger_logs` 继续负责词条与 AI 检索统计。新增通用运营事件只保存统计所需元数据：事件类型、群号、功能键、结果、耗时、时间和白名单化扩展字段。

运营事件不得保存：

- 完整群消息正文。
- AI 问题与回答正文。
- 自定义命令中的自由文本参数原文。
- 入群验证消息副本。
- 密钥、Cookie、Token 或上游原始错误响应。

活跃用户统计使用服务端密钥计算的稳定 HMAC 标识，不在运营事件中保存原始 QQ。明细事件采用有限保留期，长期趋势使用自然日聚合表；保留期清理失败只记录运维错误，不影响 bot 正常消息处理。

核心事件包括：

- 群消息收到。
- 内置或自定义命令成功、拒绝、解析失败、执行失败。
- AI 成功、繁忙、禁用、超时、审查拒绝及耗时。
- 引用图 GIF 成功、PNG 回退、失败及耗时。
- 链接净化成功与失败。
- 入群申请收到、AI 解析、人工/自动决策。
- 定时任务发送成功与失败。

## 12. 数据模型调整

现有三张表继续保留：`knowledge_trigger_logs`、`scheduled_jobs`、`group_join_requests`。

新增或扩展的数据职责：

| 表 | 用途 |
| --- | --- |
| `admin_users` | 本地账号、密码哈希参数、角色、状态、登录信息 |
| `admin_sessions` | 服务端会话、过期时间、撤销状态和安全元数据 |
| `admin_audit_logs` | 追加式管理操作审计，保存操作者、目标、前后值、结果 |
| `managed_groups` | NapCat 群元数据最后成功快照，不作为群权限真源 |
| `feature_settings` | 全局设置与群级覆盖，包含修订版本和验证后的配置 JSON |
| `custom_commands` | 命令名称、参数、动作、权限、作用域、启停和修订版本 |
| `custom_command_runs` | 自定义命令分步执行结果，不保存自由文本参数原文 |
| `group_join_decisions` | 追加式审批尝试、规则快照、操作者、NapCat 结果和幂等键 |
| `scheduled_job_runs` | 定时任务及测试发送的执行结果和耗时 |
| `bot_operation_events` | 有保留期的运营事件元数据 |
| `bot_operation_daily` | 长期自然日聚合统计 |

`group_join_requests` 增加明确决策状态、修订版本和最后决策引用。`scheduled_jobs` 增加可编辑修订版本；停用仍采用状态字段，不物理删除历史任务。

所有 schema 变更遵循 Jxh-Go 的 schema-first 约束：更新初始化 SQL，并为已有部署提供顺序明确的迁移脚本；运行时不使用 `AutoMigrate`。

## 13. 管理 API 边界

API 统一位于 `/api/admin/v1`，按资源组织：

- `/auth/login`、`/auth/logout`、`/auth/me`
- `/overview`
- `/groups`、`/groups/{group_id}`、`/groups/{group_id}/settings`
- `/join-requests`、`/join-requests/{id}`、`/join-requests/{id}/decisions`、`/join-requests/bulk-decisions`
- `/commands`、`/commands/{id}`、`/commands/{id}/validate`
- `/scheduled-jobs`、`/scheduled-jobs/{id}`、`/scheduled-jobs/{id}/test-send`、`/scheduled-jobs/{id}/runs`
- `/knowledge/status`、`/knowledge/entries`、`/knowledge/reload`
- `/analytics/summary`、`/analytics/timeseries`、`/analytics/export`
- `/audit-logs`
- `/users`、`/sessions`
- `/system/health`、`/system/napcat/restart`
- `/events`，用于授权后的 SSE 更新

列表接口使用游标或稳定排序分页，不把全量申请和审计日志一次返回浏览器。导出由授权 API 流式下载，不再只返回 bot 容器中的本地文件路径。

成功响应返回资源或结果；错误使用稳定结构：

```json
{
  "error": {
    "code": "join_request_conflict",
    "message": "该申请已被其他维护人员处理",
    "request_id": "request-trace-id",
    "fields": {}
  }
}
```

面向用户的错误不包含上游原始响应、DSN、文件绝对路径或密钥。详细上下文只进入经过脱敏的服务端日志。

## 14. 并发、失败与降级

- 写操作使用修订版本或 `If-Match` 做乐观并发控制；冲突返回 HTTP 409。
- 审批和其他不可安全重复的操作使用幂等键；未知结果不直接重试外部副作用。
- NapCat 未连接时，依赖实时 OneBot 的按钮显示不可用，API 返回可识别的 503，数据库不伪造成功状态。
- 数据库不可用时，登录后写操作失败关闭；消息管线可继续使用最后一份有效内存设置，但无法记录统计时只降级统计能力。
- 设置更新失败保留旧快照；WPS 重载失败保留旧知识索引和有效缓存。
- 自定义命令动作部分成功时停止剩余动作，并保存每一步结果。
- 定时发送只有实际发送成功后才更新 `last_run_at`；NapCat 发送失败时任务保持可重试。
- SSE 断开不影响业务操作，前端退化为显式刷新并自动重连。
- 所有后台循环以单轮 panic 恢复和上下文取消保护，管理功能故障不能让消息消费循环退出。

## 15. 健康与可观测性

- `/healthz` 保持轻量存活检查，不执行慢依赖请求。
- 增加就绪检查，区分进程存活与数据库/NapCat 是否可提供管理操作。
- 管理系统页展示 NapCat 连接、MySQL 探测、WPS 最近同步、AI 配置可用性、quote 最近探测和调度器最近 tick。
- 每个管理 API 请求生成请求 ID，审计、应用日志和上游调用日志可通过请求 ID 关联。
- 指标与日志中不记录密码、会话令牌、WPS SID、AI Key、OneBot Token、数据库密码和完整申请验证消息。

## 16. 前端交互约束

- 这是高频运维后台，采用安静、紧凑、可扫描的布局，不使用营销式大标题或装饰性卡片堆叠。
- 页面级状态、筛选和批量操作保持固定位置，表格列支持合理的窄屏收缩或切换详情布局。
- 高风险操作使用明确动词、影响范围和确认对话框，不能只靠颜色表达风险。
- 加载、空数据、权限不足、依赖离线、部分失败和数据陈旧都必须有独立状态。
- 用户提交后按钮进入稳定的进行中状态，防止重复审批或重复发送。
- 视觉方向、色彩令牌和组件行为以 `2026-07-28-jxh-manager-ui-design.md` 为准；具体前端组件库仍在实现前单独选择。

## 17. 测试与验收

当前 Jxh-Go 没有 `*_test.go`，`go test ./...` 只能证明包可编译。管理端引入登录、审批和自动化后必须新增针对业务行为的测试。

### 17.1 后端测试

- 鉴权：密码验证、速率限制、会话轮换、撤销、CSRF 和每个角色的允许/拒绝矩阵。
- 设置：继承、群级覆盖、校验失败、修订冲突和运行时快照原子替换。
- 命令：完整名称匹配、参数边界、内置冲突、权限提升防护、动作顺序和部分失败。
- 审批：`flag` 原样传递、人工批准/拒绝、并发决策、幂等、超时未知结果和系统同步不降级状态。
- 自动批准：默认关闭、按群启用、三个字段条件、格式失败回退人工、绝不自动拒绝。
- 定时任务：编辑、暂停、恢复、测试发送、发送失败重试和单次任务成功停用。
- 统计：事件脱敏、自然日边界、按群筛选、保留期和导出时区。
- 适配器：使用 fake NapCat、fake WPS、fake AI 和 fake quote，不依赖真实 QQ 完成单元测试。

### 17.2 API 与前端测试

- MySQL 集成测试覆盖事务、唯一约束、分页和迁移后的查询。
- API 测试覆盖错误代码、输入限制、敏感字段不返回和导出权限。
- 前端组件测试覆盖三态设置、审批冲突、批量确认和角色控制。
- Playwright 端到端测试覆盖登录、群设置、人工审批、自定义命令创建、定时任务和审计追踪。
- 桌面与移动视口检查文字截断、表格退化、弹窗和操作按钮不重叠。

### 17.3 外部联调边界

真实 NapCat 审批、禁言、跨群发送、WPS 下载、AI 解析和 quote 生成必须在隔离测试群完成联调。静态编译和 fake 测试不能被描述为真实 QQ 行为已验证。

## 18. 交付拆分

整体设计作为同一产品目标，但实施分为三个可独立验收的阶段：

### 阶段一：基础平台

- 管理 API 框架、HTTPS 部署边界。
- 本地账号、会话、三档 RBAC、CSRF。
- 审计基础、群列表快照、系统健康。
- 全局和群级功能设置及运行时快照。

### 阶段二：核心运营

- 入群申请列表、人工/批量决策和按群自动批准。
- 定时任务完整生命周期和执行历史。
- WPS 知识库状态、重载与只读搜索。
- 现有词条统计、申请统计和可下载导出。

### 阶段三：自动化与扩展统计

- 受控自定义命令和动作执行记录。
- 群消息量、命令、活跃用户、AI、链接净化和引用图运营统计。
- 总览趋势、详细下钻和告警式待办聚合。

每个阶段都在同一模块化架构内完成，但分别编写实施计划和验收清单。阶段一不预先实现阶段三的抽象，只保留已经在本设计中确定的数据和服务边界。

## 19. 已确认决策

- 管理端只面向内部维护团队，但必须有登录鉴权。
- 使用本地独立账号，不使用共享密码。
- 使用超级管理员、维护员、观察员三档角色。
- 采用同一 Go 进程内的模块化管理 API。
- 支持现有功能的全局与按群开关、文案设置。
- 自定义命令首版采用受控动作模板，并包含文本回复。
- 自动批准按群默认关闭，开启后以 AI 三字段完整且格式有效为条件。
- 自动化不自动拒绝申请。
- 统计同时覆盖现有业务数据和新增运营数据。
- WPS 继续作为知识库唯一数据源，管理端只读。
- 页面功能范围与“珊瑚红事务台”UI 视觉规范均已确认，具体组件库仍在前端实现前选择。
