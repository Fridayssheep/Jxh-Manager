# Jxh Manager 交互一致性与入群审批分页设计

## 1. 目标

本轮修复管理端中同类交互行为不一致的问题，使弹窗、抽屉、二级导航、下拉菜单、筛选操作、动态提示和列表更新遵循同一套视觉与动效规则。同时将入群审批从追加式长列表改为卡片内滚动的游标分页。

本设计延续“珊瑚红事务台”规范：中性表面承载信息，品牌红粉只表示当前选择和普通主操作，危险语义继续使用独立危险色。

## 2. 已确认根因

1. 弹窗和抽屉由各页面直接渲染遮罩，没有共享的 Vue Transition，因此打开和关闭均为瞬移。
2. 账号、知识库和群设置二级导航使用各自的静态底边线，无法像侧边栏一样由单一高亮层在选项之间移动。
3. `AppSelect` 仅接入统计页，其他页面仍保留浏览器原生下拉菜单。
4. 筛选按钮尺寸由页面局部 CSS 决定，网格压缩时文字按钮允许收缩，图标按钮也没有统一的稳定布局。
5. 操作结果和错误提示由各页面直接插入 DOM，缺少统一换行策略和内容变化 revision，导致长英文错误被极端断行，并且提示闪现。
6. 入群审批 API 已提供 `next_cursor` 和 `has_more`，但页面将下一批数据追加到当前数组，因此列表持续增长并撑高页面。

## 3. 共享交互基础

### 3.1 弹窗与抽屉

新增 `AppOverlayTransition`。业务页面仍拥有弹窗内容和提交逻辑，组件只负责进退场：

- 遮罩在 220ms 内淡入淡出。
- 居中弹窗从 `opacity: 0; transform: translateY(10px) scale(0.985)` 进入自然位置。
- 右侧抽屉从 `translateX(24px)` 进入自然位置。
- 离场使用相同层级的反向动画。
- `prefers-reduced-motion: reduce` 下取消位移并把时长缩短到近乎即时。

迁移范围包括入群审批决策、审计详情、命令相关弹窗、知识库重载、定时任务编辑与二次确认、系统危险操作、账号编辑与二次确认。

### 3.2 滑动高亮和内容切换

提取侧边栏现有的单一高亮层测量方式为 `useSlidingIndicator`，使用目标元素和容器的 `getBoundingClientRect()` 计算尺寸与位移，并在 resize、选项变化和布局变化后重新测量。

新增 `AppTabBar`：

- 选项使用真正的 `role="tab"`、`aria-selected` 和键盘方向键导航。
- 高亮由一个绝对定位的淡粉表面在选项间移动，不为每个选项创建独立伪元素。
- 内容区域使用 keyed Transition；旧内容淡出，新内容上浮 8px 淡入。
- 账号与会话、知识库视图以及群设置二级导航使用同一移动高亮流程。

入群审批选中行同样使用单一高亮层，左侧 3px 品牌标记包含在高亮层内，移动过程与侧边栏一致。

### 3.3 动态内容

现有 `vRiseOnChange` 继续作为内容更新基础：

- 列表成功加载、页签内容切换、详情切换、操作提示出现或文案改变时触发上浮淡入。
- 请求开始、失败后仍展示旧数据、过期响应均不能推进数据 revision。
- 高度变化使用 `vSmoothResize`，避免提示、表格和详情区突然改变高度。

新增 `OperationNotice` 统一成功、警告、危险和未知结果的图标、关闭按钮、ARIA role、换行与上浮行为。消息容器必须设置 `min-width: 0`、`overflow-wrap: anywhere` 和正常单词换行，不能把每个单词压成单独一行。

## 4. 表单控件与按钮

仓库中所有用户可见的原生 `<select>` 迁移到 `AppSelect`，包括：

- 总览、群目录、入群审批、命令目录与命令编辑器。
- 定时任务目录和编辑抽屉。
- 知识库、审计、账号与会话。
- 命令参数及动作编辑子组件。

`AppSelect` 保持现有 Teleport、视口翻转、键盘导航和隐藏表单值行为。迁移只改变可见控件，不改变筛选参数、路由状态或 API 请求。

筛选操作统一满足：

- 文字按钮 `min-inline-size: 84px`、`white-space: nowrap`、禁止被网格压缩到文字溢出。
- 清空按钮固定为 `38px x 38px`，使用 grid 居中，图标不受基线和 flex 剩余空间影响。
- 窄屏时筛选网格换行或降为两列/一列，不通过继续压缩按钮解决空间不足。

## 5. 入群审批分页与滚动

### 5.1 分页数据流

- 每页请求明确提交 `limit: 10`。
- 当前页只渲染本次响应的 `items`，不再追加。
- 页面维护已访问游标历史：第一页游标为 `null`；前进时记录当前响应的 `next_cursor`；后退时复用历史游标。
- 分页栏显示“第 N 页”、上一页和下一页。因为后端是游标分页，不展示无法随机跳转的伪页码或总页数。
- 筛选、排序和显式刷新回到第一页。
- 翻页时清除当前批量选择、详情和活动行，避免隐藏条目继续参与操作。
- 决策成功后刷新当前页；若非第一页被处理为空，则自动返回上一页。

### 5.2 布局

- 宽屏审批工作区仍为列表与详情双栏。
- 队列卡片使用稳定高度约束，主体列表为 `minmax(0, 1fr)` 并在卡片内部 `overflow-y: auto`。
- 分页栏位于卡片底部，不随列表内容滚走。
- 移动端工作区改为单列，队列仍在卡片内滚动，不产生页面横向溢出。

## 6. 测试与验收

### 6.1 单元测试

- `AppOverlayTransition`：居中弹窗、抽屉和减少动态效果类名/结构。
- `useSlidingIndicator` / `AppTabBar`：高亮尺寸与位移、键盘切换、内容上浮。
- `OperationNotice`：tone、ARIA role、长错误文案与 revision 动画。
- 各迁移页面：不再渲染原生 `<select>`，筛选和编辑请求保持原参数。
- 入群审批：每页 10 条、下一页/上一页游标、翻页替换数据、选择与详情清理。

### 6.2 E2E 与视觉验收

- 1440x1024、1024x768、390x844 三个视口无横向溢出或按钮文字越界。
- 新建定时任务、二次确认、账号确认和 NapCat 重启均有真实进退场动画。
- 账号页签和审批活动行高亮移动后与目标元素位置一致。
- 所有页面不存在可见原生 `<select>`。
- 入群审批列表在卡片内滚动，分页请求使用正确游标，详情和列表更新有上浮动画。
- 长 NapCat 错误信息保持可读短语换行，不闪现、不逐词独占一行。

## 7. 非目标

- 不修改后端分页契约，也不把游标分页改为 offset/page-number 分页。
- 不引入新的完整 UI 组件库。
- 不改变权限、审批幂等、资源版本或业务字段语义。
