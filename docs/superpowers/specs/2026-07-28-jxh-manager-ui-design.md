# Jxh Manager UI 视觉与交互规范

- 日期：2026-07-28
- 状态：已确认（Figma 首版视觉基准已建立，品牌色值仍待完整品牌资产校准）
- 适用范围：Jxh Manager 管理端 SPA
- 产品依赖：`2026-07-27-jxh-manager-design.md`
- API 依赖：`2026-07-27-jxh-manager-api-design.md`
- 视觉基准：[Jxh Manager - 珊瑚红事务台](https://www.figma.com/design/yVxKAtRLaIOM2mlCezvP4G)

## 1. 目的与边界

本文定义 Jxh Manager 的视觉方向、设计令牌、布局、组件语义、响应式与可访问性要求。页面功能、角色权限和业务流程继续以总体设计与 OpenAPI 为准。

当前仓库已有精小弘首版 Logo 位图与描摹 SVG，并已在 Figma 方向稿中验证角色头像与红粉主题的适配性；但仍缺少经过优化的小尺寸标志、单色标志、完整标准色板和正式品牌字体文件。因此本文色值继续作为首版设计令牌。完整品牌资产到位后可以校准 `brand-*` 令牌，但不得借此改变语义色、危险操作规则、对比度门槛或组件行为。

本文不选择具体前端框架和组件库。后续技术选型必须能够表达本文令牌和交互状态，不能让组件库默认主题反向决定产品风格。

## 2. 设计方向

设计主题命名为“珊瑚红事务台”。它把精小弘鲜艳的红色和粉色集中用于品牌识别、当前选择和普通主操作，主体仍保持安静、紧凑和可扫描的运维工具感。

整体视觉比例遵循：

```text
80% 中性灰白：页面、表格、表单和阅读区域
15% 淡粉表面：当前选择、轻提示和品牌关联状态
 5% 高饱和红：品牌标记、焦点和关键普通操作
```

品牌辨识度由贯穿侧栏和页面标题的“红粉事务轨道”承担，而不是依靠大面积粉色背景、装饰性卡片或强阴影。主界面应像可靠的内部操作工具，登录页和空状态可以适当提高品牌浓度。

### 2.1 NapCat UI 参考边界

NapCat 的粉色 WebUI 可以作为气质与应用框架参考，但不是逐像素复刻目标。Jxh Manager 从中继承：

- 左侧稳定品牌区、细竖向品牌轨道和图标加文字导航。
- 当前导航使用淡粉底与亮色标记，不用大面积实心红。
- 外层应用框架允许非常低浓度的粉色环境光，使白色内容区域不显生硬。
- 同一资源内使用横向二级页签，当前页签以品牌红文字和下划线确认。
- 登录、空状态和低信息密度页面可以有限使用精小弘角色视觉资产。

结合 Jxh Manager 的高频审批、审计和宽表格场景，必须做以下调整：

- 提高正文、辅助文字、边框和禁用状态的对比度，不能使用接近背景的浅灰文字。
- 页面圆角收敛到 4px 至 8px，不采用大面积 16px 以上圆角容器。
- 减少浮动卡片数量；筛选、表格和详情优先使用全宽区域与分隔线。
- 粉色环境光只存在于应用外框、侧栏或登录背景，数据表格和图表画布保持中性。
- 角色插画不能压在图表、仪表、状态数字或表单内容后方，也不能降低数据可读性。
- 右侧装饰点、短线或胶囊不能伪装成可点击控件或状态指示。

因此，NapCat 是“品牌氛围与导航框架”的参考，Jxh Manager 自己的密度、危险语义、状态完整性和可访问性仍以本文为准。

### 2.2 Figma 首版视觉基准

Figma 文件 [Jxh Manager - 珊瑚红事务台](https://www.figma.com/design/yVxKAtRLaIOM2mlCezvP4G) 中的 `01 Overview` 页面是本规范的首个视觉基准。其 `Dashboard / Desktop` 框架以 `1440 x 1024` 桌面视口验证公共应用壳、品牌密度、导航层级和 KPI 表现。后续设计与 Vue 实现应以该方向稿作为视觉校准对象，而不是重新选择一套后台风格。

方向稿已确认以下表现：

- 展开侧栏为 224px，最左侧使用连续 4px `brand-500` 事务轨道；侧栏主体保持白色。
- 品牌区使用 40px 精小弘角色头像、中文名称和紧凑英文副标，不把完整角色插画铺进数据区域。
- 一级导航高 40px、图标 18px；当前项使用 `brand-surface`、`brand-ink` 和左侧品牌标记，待审批计数使用独立警告色标签。
- 业务导航位于侧栏上部；审计、账号与系统入口固定在下部；全局依赖健康度以紧凑工具面板收尾。
- 顶部工具栏高 52px，提供当前群范围、实时同步、刷新与当前账号入口，内容区水平内边距为 24px。
- 总览页标题使用 24px 上限；KPI 为单行四项、104px 高、6px 圆角的紧凑重复项，不使用营销级大数字。
- 群消息趋势可使用品牌色强调；待审批使用警告语义；命令成功率和 AI 请求分别使用成功与信息语义，不用四种红粉深浅代替分类。
- 数据工作区保持 `canvas` 与 `surface` 中性色，不使用环境光球、强阴影、玻璃拟态或插画衬底。

该方向稿当前只完成公共应用壳、页面头部和 KPI 首行。主内容下半区的大面积空白来自 Figma Starter MCP 调用限额，不是最终留白设计，也不得在前端实现中照搬。总览页仍必须按第 9.2 节补齐“需要处理”和“系统健康”区域，其中待处理事项优先于装饰性图表。

方向稿中的统计数字、审批数量和运行状态均为布局样例，不构成产品默认值、接口契约或演示数据要求。响应式布局、交互状态、表格、弹窗和危险操作仍以本文其他章节与总体产品设计为准。

发生差异时按以下顺序处理：

1. 业务能力、权限和数据含义以总体设计和 OpenAPI 为准。
2. 语义色、可访问性、危险操作和组件行为以本文为准。
3. 在不违反前两项的前提下，公共应用壳、尺寸、密度和视觉层级以 Figma 基准为准。
4. Figma 与本文出现无法解释的冲突时，先更新并评审本文，再修改 Figma 或前端，不允许静默选择其中一方。

## 3. 设计原则

1. 信息优先：表格、筛选、状态和影响范围优先于装饰。
2. 品牌集中：鲜艳红粉只出现在稳定且有限的位置。
3. 语义独立：品牌红、成功、警告、危险和信息色不能互相替代。
4. 状态完整：加载、空数据、无权限、离线、陈旧、部分失败、冲突和未知结果均有独立表现。
5. 操作稳定：提交后控件保持尺寸并进入明确的进行中状态，防止重复操作。
6. 桌面优先：为高频运维和宽表格优化，同时为窄屏提供真正的列表与详情布局。
7. 克制动效：动效只说明状态变化和层级，不承担装饰性表演。

## 4. 色彩系统

### 4.1 品牌色

| Token | 色值 | 用途 |
| --- | --- | --- |
| `brand-500` | `#F04464` | Logo、选中轨道、图表主序列和非文字装饰 |
| `brand-action` | `#D82F54` | 普通主按钮、开关激活和重要可交互元素 |
| `brand-action-hover` | `#BD2347` | 主按钮悬停和按下 |
| `brand-pink` | `#FF8EAF` | 对比序列和少量品牌细节 |
| `brand-surface` | `#FFF0F4` | 当前导航、选中行和品牌轻提示背景 |
| `brand-border` | `#F5B8C7` | 品牌浅色表面的边界 |
| `brand-ink` | `#7B2036` | 淡粉表面上的强调文字 |

`brand-500` 与白色的对比度不足以承载普通字号白字，因此实心主按钮必须使用 `brand-action` 或更深颜色。`brand-500` 只用于图形、轨道、大号标记或在浅色背景上的非正文元素。

### 4.2 中性色

| Token | 色值 | 用途 |
| --- | --- | --- |
| `canvas` | `#F7F7F5` | 页面背景 |
| `surface` | `#FFFFFF` | 表格、表单、弹窗和工具区域 |
| `surface-subtle` | `#F1F3F1` | 次级区域、禁用状态和表头 |
| `text-primary` | `#222524` | 正文与主要数字 |
| `text-secondary` | `#6D7470` | 描述、时间和辅助字段 |
| `text-disabled` | `#929995` | 禁用文字 |
| `border` | `#D8DDDA` | 常规边框与分隔线 |
| `border-strong` | `#B8BFBB` | 聚焦前的强边界和拖拽边界 |

页面不能被白色卡片切割成大量浮岛。相邻功能区优先使用留白、分隔线和全宽带状背景组织；总览下半区的趋势、待处理和系统健康属于需要明确边界的工具面板，应使用带边框的圆角卡片。

### 4.3 语义色

| 语义 | 前景色 | 浅色表面 | 用途 |
| --- | --- | --- | --- |
| 成功 | `#18835A` | `#EAF7F1` | 在线、批准、成功和健康 |
| 警告 | `#A25E00` | `#FFF6E6` | 等待、陈旧、接近超时和降级 |
| 信息 | `#3167A5` | `#EDF4FC` | 普通提示、同步和外部来源 |
| 危险 | `#9F2525` | `#FDEEEE` | 拒绝、删除、失败和高风险系统动作 |
| 未知 | `#6D7470` | `#F1F3F1` | 未确认结果和尚未检查 |

状态不得仅通过颜色传达。所有状态至少同时提供图标或形状、文字标签和必要的时间信息。

### 4.4 品牌红与危险红

这是整套设计的强制规则：

- 品牌红表示品牌、当前选择、焦点和普通主操作。
- 危险红使用更深、更暗的 `#9F2525`，不得使用粉色。
- 批准使用成功色；拒绝使用危险色描边；NapCat 重启仅在最终确认中使用危险色实心按钮。
- 危险按钮必须包含明确动词，不能只写“确定”。
- 高风险确认必须同时展示对象、影响范围和不可逆后果，不能只靠按钮颜色制造警告。

## 5. 排版

### 5.1 字体

```css
--font-ui: -apple-system, BlinkMacSystemFont, "Segoe UI", "Microsoft YaHei", "PingFang SC", "Hiragino Sans GB", "Noto Sans CJK SC", sans-serif;
--font-mono: "IBM Plex Mono", "Noto Sans Mono CJK SC", monospace;
```

- 界面优先使用系统 UI 字体；中文在 Windows 使用 `Microsoft YaHei`，在 Apple 平台使用 `PingFang SC`，并保留 CJK 后备字体。
- QQ、群号、请求 ID、版本、时间和代码值使用等宽字体。
- 不使用超大营销标题；页面标题上限为 24px。
- 字间距统一为 0，不随视口宽度缩放字号。

### 5.2 字号层级

| 层级 | 字号/行高 | 用途 |
| --- | --- | --- |
| 页面标题 | `24/34` | 页面唯一主标题 |
| 区域标题 | `20/28` | 全宽功能区标题 |
| 面板标题 | `16/24` | 紧凑工具面板和弹窗标题 |
| 正文 | `14/22` | 表格、表单和描述 |
| 辅助 | `12/18` | 标签、时间和元数据 |

数据数字可以使用 `16/24` 或 `20/28`，但不能因为放入 KPI 项就使用首屏宣传级字号。

## 6. 空间与形状

- 使用 4px 基础间距：`4, 8, 12, 16, 20, 24, 32`。
- 图标按钮稳定尺寸为 36px 或 40px；常规表单控件高度为 40px。
- 普通控件圆角 4px，工具面板 6px，弹窗和抽屉不超过 8px。
- 状态标签可以使用短胶囊，但导航、按钮、输入框和大块容器不得全部胶囊化。
- 阴影只用于弹窗、抽屉、下拉层和拖拽浮层；普通页面区域不使用悬浮阴影。
- 卡片只用于重复 KPI、重复实体和确实需要边界的工具，不允许卡片嵌套卡片。

## 7. 应用框架

### 7.1 桌面布局

- 展开侧栏宽 224px，折叠侧栏宽 64px。
- 顶部工具栏高 52px，页面水平内边距 24px。
- 内容区域默认使用可用宽度，不设置营销站式窄版最大宽度。
- 页面标题、范围选择、刷新和主操作位于固定的页面头部。
- 筛选条和批量操作条在长列表滚动时保持可达。

侧栏最左侧保留 4px 的红粉事务轨道。当前导航使用 `brand-surface` 背景、`brand-ink` 文字和 `brand-500` 轨道标记，不使用实心红色大色块。

侧栏底部或顶部工具栏提供紧凑的全局运行状态入口，显示 NapCat、MySQL、WPS 和 SSE 的汇总状态。它是状态工具，不是装饰灯带。

### 7.2 响应式

- `>= 1280px`：展开侧栏、完整表格和并列详情。
- `768px - 1279px`：折叠侧栏，可隐藏低优先级表格列。
- `< 768px`：导航进入抽屉；宽表格切换为摘要列表和独立详情，不使用水平压缩文字。

移动端保留审批、查看状态和紧急暂停能力，但自定义命令编排、复杂统计对比等高密度工作流可以提示使用更宽视口。

## 8. 核心组件规范

### 8.1 按钮

- 普通主操作：`brand-action` 实心背景。
- 次要操作：白底、`border` 边界和主要文字。
- 批准：成功色实心或浅色表面。
- 拒绝与删除：危险色描边；仅最终确认使用危险色实心。
- 图标操作优先使用 Lucide 图标，并为不熟悉的图标提供 Tooltip。
- 加载时保留原尺寸，显示旋转指示并禁用重复提交。

### 8.2 导航

- 导航项高度 40px，图标 18px。
- 待审批数量显示为固定宽度计数，不改变导航项布局。
- 当前项依赖淡粉表面和左侧轨道，不依赖红色文字本身。
- 用户、审计与系统入口保持稳定位置，不随业务列表增长漂移。

### 8.3 表格与列表

- 常规行高 44px，高信息行可使用 52px，表头保持粘性。
- QQ、群号、状态、时间和操作列使用稳定宽度。
- 主字段允许两行，其他长文本截断并通过详情或 Tooltip 查看。
- 行悬停使用中性浅灰；选中使用淡粉表面和左侧品牌标记。
- 行内操作最多保留两个常用动作，其余进入菜单。
- 批量选择后出现固定批量操作条，并明确显示选中数量与群范围。

### 8.4 表单与设置

- 标签位于控件上方，校验信息位于对应字段下方。
- 功能设置按全宽分组组织，不为每个开关创建独立装饰卡片。
- “继承 / 启用 / 停用”使用稳定三段控件，并同时显示继承来源和值。
- 修改群级覆盖后，在提交前展示受影响群和变化摘要。
- 版本冲突保留用户未提交内容，并提供重新读取与比较入口。

### 8.5 状态标签

状态标签包含状态图标、文字和浅色表面。未知枚举显示原始值的安全格式化结果，并使用未知状态样式，不能导致页面崩溃或空白。

“陈旧数据”必须显示最后成功时间；“结果未知”必须与“失败”分开；“部分成功”必须显示成功、失败和未知数量。

### 8.6 对话框与抽屉

- 普通确认弹窗宽 480px，高风险确认可到 560px。
- 详情抽屉宽 520px 至 640px；复杂审批在宽屏优先使用页面内双栏。
- 不在弹窗内继续打开第二层弹窗。
- 高风险确认的危险按钮位于操作区末端，并与取消按钮保留至少 12px 间距。

## 9. 页面应用

### 9.1 登录

登录页可以提高品牌色占比，但登录表单本身保持单一清晰焦点。不得使用营销 Hero、功能介绍或虚假数据。失败提示不能透露账号是否存在或被停用。

### 9.2 总览

KPI 采用一行紧凑重复项，卡片圆角不超过 6px。最近趋势、需要处理和系统健康均使用与 KPI 一致的浅灰边框、6px 圆角和统一外缘内边距。品牌红只用于最主要趋势，健康度和待办按语义色展示。“需要处理”区域比装饰性图表优先。

### 9.3 群与设置

群列表以表格为主。群详情使用全宽分区展示有效设置、覆盖来源、自动批准策略、任务和近期活动。淡粉只标记当前选中的群或已修改字段。

### 9.4 入群审批

宽屏使用“申请与 AI 提取信息 / 决策时间线与操作”双栏。批准按钮使用成功色，拒绝按钮使用危险色描边；选中申请使用品牌淡粉，不使用危险色。

### 9.5 自定义命令

编辑器按“基础信息、参数、权限与范围、动作序列、无副作用测试”纵向展开。动作序列使用编号和明确类型图标，拖拽不能成为唯一排序方式。

### 9.6 定时任务与知识库

定时任务突出下次运行、状态和最近结果。测试发送使用品牌主操作，但必须与正式启停分开。知识库为只读界面，编辑型视觉和保存按钮不得出现。

### 9.7 统计

主序列使用 `brand-action`，上一周期使用 `brand-pink`。多序列依次使用信息、成功、警告和青绿色，不得使用六种红粉深浅代替分类。图表必须配有数值、图例或表格替代。

### 9.8 审计、账号与系统

审计变化前后值使用结构化差异视图。账号停用、密码重置、会话撤销和 NapCat 重启遵循危险操作规则。系统依赖状态使用固定顺序和语义色，不把不同故障压成单一红色总状态。

## 10. 数据状态

| 状态 | 表现要求 |
| --- | --- |
| 加载 | 保持最终布局尺寸，使用局部 Skeleton 或进度状态 |
| 空数据 | 说明当前筛选下无结果，并提供相关清除筛选或创建动作 |
| 无权限 | 展示权限不足，不伪装为空数据 |
| 依赖离线 | 标明依赖、影响能力和最后成功时间 |
| 数据陈旧 | 使用警告色并显示快照时间 |
| 部分失败 | 分项展示成功、失败与未知，不只显示 Toast |
| 版本冲突 | 保留用户输入，展示资源已变化并引导比较 |
| 结果未知 | 使用未知样式，提供重新同步或刷新动作 |
| SSE 断开 | 显示低干扰连接状态，并退化为显式刷新 |

Toast 只用于操作回执，不能承载必须持续可见的错误、冲突或依赖状态。

## 11. 动效

- 控件状态变化使用 120ms 至 180ms。
- 抽屉和弹窗使用 180ms 至 240ms。
- 表格刷新不使用整页淡出；只更新受影响行和时间信息。
- SSE 更新可以短暂高亮对应行，但不得改变行高或触发布局跳动。
- 遵守 `prefers-reduced-motion`，关闭位移和非必要闪动。
- 不使用装饰性粒子、视差、背景光球或循环动画。

## 12. 可访问性

- 普通文字与背景对比度至少 4.5:1；大号文字和必要图形至少 3:1。
- `brand-action` 上的白字对比度约 4.7:1；`brand-500` 不承载普通白字。
- 键盘焦点使用 2px `brand-action` 轮廓和 2px 外偏移，不得只改变背景色。
- 所有功能都可通过键盘完成，逻辑顺序与视觉顺序一致。
- 触控目标最小 40px；紧凑表格中的图标按钮仍保持稳定点击区域。
- 图标按钮具有可访问名称；状态、图表和确认不能只靠颜色表达。
- 文字放大到 200% 时不遮挡、重叠或丢失关键操作。

## 14. 禁止模式

- 覆盖数据内容的大面积红粉渐变、玻璃拟态、霓虹发光和深色赛博控制台；应用外框允许低浓度粉色环境光。
- 页面由大量悬浮卡片组成，或在卡片中继续嵌套卡片。
- 所有图表序列都使用红粉色，只靠深浅区分。
- 将品牌红同时用于普通选择、失败和危险操作。
- 大标题、宣传文案、产品功能介绍占据首屏。
- 表格在移动端被强制压缩到无法阅读。
- 通过颜色隐藏权限或状态差异。
- 用 Toast 代替持久错误、版本冲突和部分失败详情。

## 15. 验收清单

- 所有页面能明确识别精小弘品牌，但主体仍以中性色为主。
- 品牌红与危险红在颜色、图标、文案和交互上均可区分。
- 主要正文、按钮、焦点和状态颜色达到对比度要求。
- 页面头部、筛选、批量操作和表格列在同类页面保持一致。
- 加载、空数据、无权限、离线、陈旧、部分失败、冲突和未知状态均有设计。
- 宽屏与移动视口不存在文字、工具栏、弹窗和操作按钮重叠。
- 自定义命令、审批和 NapCat 重启等高风险流程不能因视觉简化而丢失影响范围或确认步骤。
- 图表提供非颜色信息，未知枚举和长标识符有稳定降级表现。
- `>= 1280px` 的公共应用壳与 Figma `Dashboard / Desktop` 基准在侧栏、工具栏、内容边距、字号层级和 KPI 密度上保持一致。
- 总览页补齐“需要处理”和“系统健康”区域，不把 Figma 首版方向稿的下半区空白实现为永久留白。
- 正式 Logo 与品牌色到位后只调整品牌令牌，并重新执行对比度和截图验收。
